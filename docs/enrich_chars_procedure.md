# キャラクター説明文翻訳・属性タグ抽出 手順書

## 概要

`scripts/enrichCharsV2.ts` を使って以下を行う：

1. AniList から英語の説明文を取得
2. Claude API (Haiku) で日本語翻訳
3. Claude API (Haiku) で属性タグを抽出
4. SQLファイルを生成 → Supabase SQL Editor で適用

> **重要**: Supabase の anon キーはRLSにより UPDATE 権限がない。
> 直接 supabase.update() は機能しないため、必ずSQL生成 → SQL Editor 適用の手順を踏むこと。

---

## 実行手順

### 1. テスト実行（特定アニメの先頭N人）

```bash
# 書式: npx tsx scripts/enrichCharsV2.ts [1アニメあたりの人数] [対象アニメ数]

# ダンダダン（1位）の先頭10人だけ
npx tsx scripts/enrichCharsV2.ts 10 1

# 上位3アニメの先頭10人ずつ
npx tsx scripts/enrichCharsV2.ts 10 3
```

### 2. 全400人を実行

```bash
npx tsx scripts/enrichCharsV2.ts
# デフォルト: 各アニメ上位10人 × 上位40アニメ = 約400人
```

### 3. SQL の適用

1. 生成されたSQLファイルを確認する  
   → `scripts/sql/patches/14_enrich_v2_YYYYMMDD.sql`

2. Supabase ダッシュボード → **SQL Editor** を開く

3. SQLファイルの内容を貼り付けて実行

4. 適用後、`scripts/checkFirst10.ts` で結果を確認
   ```bash
   npx tsx scripts/checkFirst10.ts
   ```

## 仕組み

### データフロー

```
Supabase（対象キャラ一覧）
        ↓
AniList API（英語 description 取得）
        ↓
Claude API Haiku（翻訳）
        ↓
Claude API Haiku（タグ抽出）
        ↓
SQLファイル生成
        ↓
Supabase SQL Editor（手動適用）
```

### キャラクターの選出基準

- 対象アニメ: `is_hidden = false` を人気順（`popularity` DESC）で上位40件
- キャラ順: `role` 優先（MAIN → SUPPORTING → BACKGROUND）→ `favourites` 降順

---

## 翻訳プロンプトの方針

- アニメタイトル・役割（主要/サブ）をコンテキストとして付与
- キャラクター名は日本語名のまま使用（翻訳・変換しない）
- スポイラータグ（`~! !~`）は除去
- 自然で読みやすい日本語を優先（直訳調を避ける）
- 500〜600文字を上限としてトリミング

## タグ品質ルール（Claude への指示）

1. **説明文・基本情報から明確に読み取れるタグのみ**選ぶ（推測・憶測は不可）
2. **同一カテゴリ内のタグは原則1つ**（例: `JK・高校生` と `高校生` は重複不可）
3. 外見・性格・役割・職業・能力など多角的に判断する

### スクリプト側の重複排除ロジック

- `Set` による完全重複除去
- `JK・高校生` と `高校生` が両方ある場合 → `高校生` を除去
- エイリアス正規化（例: `JK/高校生` → `JK・高校生`、`和服/着物` → `和服・着物`）

## 既知の課題・注意点

### AniList説明文の品質
- AniListの英語説明文自体が不正確・混乱しているケースがある  
  例: 別キャラの説明が混入、スポイラーネタバレを含む
- 説明文がない（null）キャラも多い → タグは名前・性別・年齢・身長のみで判断

### タグ精度の限界
- 説明文がないキャラは視覚情報がないため、タグが少なくなる
- 外見タグ（髪色・髪型など）は説明文に記述がない場合は付与できない
- 改善策: 将来的に画像解析（vision API）を追加することで外見タグの精度向上が見込める

### 声優情報
- AniList から日本語声優名を自動取得し、DBが空の場合のみ補完する

## 再実行時の注意

- SQLファイルは実行のたびに新しい日付付きで生成される
- 同じキャラに対して複数回実行すると、最後に適用したSQLの内容で上書きされる
- テスト → 内容確認 → 全量実行 → SQL適用 の順で進めること
